# 대화기록

메이플스토리 같은 2D 액션 RPG(`maplelike-rpg`)를 사용자와 Claude가 함께 만들어 온 대화를 단계별로 정리한 기록이다.

- Claude는 사용자에게 항상 한국어로 답한다.
- 화면 동작은 Claude in Chrome(브라우저 자동화)으로 직접 띄워 확인했다.
- 사용자의 Chrome에서 테스트하면 사용자의 localStorage 저장 데이터와 같은 곳을 쓰게 된다. 그래서 테스트 전에 저장 데이터를 백업하고 테스트 후 복원했다.

---

## 1. 계획
- **사용자 요청**: 메이플스토리 같은 2D 게임에 다른 게임의 요소를 섞고 싶다. 처음에는 "아주 기초적인 단계부터" 시작하길 원했다.
- **진행/결과**: 질문으로 방향을 정했다.
  - 기술: Phaser 3 + TypeScript
  - 섞을 요소: 액션 콤보(던파/할로우나이트) + 수집/파밍(디아블로)
  - 싱글 플레이, 그래픽은 임시 도형으로 시작
  - 마일스톤 M0~M6 계획을 `docs/PLAN.md`에 저장했다.
- **결정**: 이번 범위는 M0 셋업과 가장 기초적인 이동까지만.

## 2. M0 셋업 + 기초 이동
- **사용자 요청**: 가장 기초 단계부터 시작.
- **진행/결과**: Vite/TS/Phaser 프로젝트를 직접 구성했다. 바닥과 발판, 네모 플레이어의 좌우 이동·점프, 카메라 추적을 구현했다.
- **결정**: 환경이 Node 18이라 Vite 5, Vitest 2를 사용했다.

## 3. 키 입력 끊김 버그
- **사용자 요청**: 키를 한 번 누르면 다음 키가 먹히지 않고, 화면을 클릭해야 다시 된다.
- **진행/결과**:
  1. 처음엔 Alt 키의 브라우저 메뉴 포커스 문제로 보고 고쳤다. 사용자가 "모든 키가 그렇다"고 알려 줬다.
  2. 진단 패널을 만들어 이벤트를 확인했다. 시크릿 모드에서는 정상이었다. 원인은 크롬 확장 프로그램의 간섭이었다.
  3. 사용자가 이전 프로젝트 `../paladog`에서 같은 문제를 고쳤다고 알려 줬다. 그 방식대로 Phaser 키보드 플러그인을 끄고, window의 capture 단계에서 keydown/keyup을 `e.code` 기준으로 직접 처리하도록 했다(`src/systems/KeyInput.ts`). 해결.
- **교훈**: 입력 문제는 추측하지 말고 진단 도구로 원인부터 가른다. 사용자의 과거 경험이 결정적 단서였다.

## 4. 점프 키 정리, 밧줄·사다리
- **사용자 요청**: Alt/Space 점프를 없애고 C만 쓰기. 점프력이 어느 정도인지 설명. 밧줄과 사다리 추가.
- **진행/결과**: 점프는 C 하나로 정리했고, 점프 높이는 약 137px로 안내했다. ↑↓로 밧줄·사다리를 오르내리고, ←/→+C로 뛰어내린다.

## 5. 캐릭터 픽셀아트
- **사용자 요청**: 2등신(머리 1 : 몸 1)의 팬티만 입은 남자 캐릭터.
- **진행/결과**: 16x24 픽셀 도트를 3배로 키워 그렸다.

## 6. 걷기 모션
- **사용자 요청**: 걸을 때 한 발 앞 → 서기 → 다른 발 앞 → 서기의 모션.
- **진행/결과**: 4프레임 걷기를 만들었다. 먼 쪽 다리를 어둡게 칠해 어느 다리인지 구분되게 했다.

## 7. 밧줄·사다리 뒷모습
- **사용자 요청**: 밧줄/사다리를 탈 때 뒷모습(뒤통수)으로 보이게.
- **진행/결과**: 오르내릴 때 쓰는 뒷모습 모션을 추가했다.

## 8. 범위 단위, 기본 공격, 샌드백
- **사용자 요청**: 범위 단위를 정의(플레이어 너비 = 범위 1)하고, X 키 기본 공격(주먹, 범위 1, 공격력 10), 때려볼 샌드백 추가.
- **진행/결과**: 범위 1 = 48px로 정했다(`src/data/units.ts`). 샌드백을 배치하고 X 공격을 구현했다.

## 9. 범위 0.5 단위
- **사용자 요청**: 0.5 단위 범위 허용, 기본 공격 범위를 0.5로. 공격 범위의 하얀 표시와 샌드백의 하얀 번쩍임은 제거.
- **진행/결과**: 소수 범위를 지원하고 기본 공격 범위를 0.5로 줄였다. 하얀 표시와 번쩍임은 없앴다.

## 10. 인벤토리
- **사용자 요청**: 96칸 인벤토리, 6x8=48칸이 보이고 스크롤, 화면의 약 1/4 크기, I 키로 열기.
- **진행/결과**: 구현 완료. 마우스 휠은 터치패드 대응을 위해 이동량을 모았다가 한 줄씩 넘기도록 했다.

## 11. 점프력 조정, 상태창
- **사용자 요청**: 점프력을 약간 낮추기. S 키 상태창: HP/MP 100, ATTACK/SPELL/HIT/MHIT, STR/CON/DEX/INT/WIS/MEN과 각 효과.
- **진행/결과**: 점프 높이를 약 120px로 낮췄다. 1포인트당 증가량처럼 정해지지 않은 수치는 Claude가 기본값으로 정하고 표로 안내했다(수치는 DEVLOG 참고).

## 12. 능력치 상한, 첫 몬스터 아기 오리
- **사용자 요청**:
  - 기본 능력치는 레벨업으로 999까지. 아이템 보너스는 무제한이며 "(+5)"처럼 표시.
  - 첫 몬스터 아기 오리: 뒤뚱뒤뚱 느리게 걷고, 닿으면 데미지, 먼저 공격하지 않음(비선공), 맞으면 화난 얼굴로 약간 빨라져 추격, 크기는 샌드백 정도.
- **진행/결과**: 구현했다. 체력, 사망, 재생성, 플레이어 피격 후 무적 같은 정해지지 않은 부분은 메이플 방식으로 보충했다.

## 13. 하단 HUD
- **사용자 요청**: 하단에 1024px 바, 왼쪽 HP 구슬과 오른쪽 MP 구슬이 남은 양만큼 차오르게.
- **진행/결과**: 구현했다.
- **문제**: Phaser의 Rectangle은 `width`를 직접 바꾸면 그려지는 크기가 바뀌지 않는 버그가 있었다. `setSize`를 쓰도록 고쳤다(상태창의 바도 같이).

## 14. HUD 다듬기
- **사용자 요청**: 구슬을 작게, 게임 화면은 HUD 위쪽까지만 사용, 어두운 바는 구슬 사이에만.
- **진행/결과**: 구슬 축소, 카메라 뷰포트를 HUD 위까지로 제한, 어두운 바를 구슬 사이에만 그리도록 변경했다.

## 15. 경험치와 레벨
- **사용자 요청**: 맨 아래 경험치바, 레벨 시스템(최대 999, 레벨업마다 포인트 10, 1→2 레벨은 오리 10마리), 상태창에 + 버튼.
- **진행/결과**: 1→2 레벨 필요 경험치는 20(오리 한 마리 2 x 10마리), 이후는 `20 x 레벨^1.5`로 정했다. 상태창의 + 버튼으로 포인트를 찍는다.

## 16. 오리 스폰
- **사용자 요청**: 오리를 10마리 유지하고, 공중 발판에서도 나오게.
- **진행/결과**: 20초마다 모자란 수만큼 채우는 스포너를 만들었다. 바닥과 모든 발판에서 나온다.

## 17. 개발자용 DEV 메뉴
- **사용자 요청**: 오른쪽 위에 마우스를 올리면 드롭다운이 나오는 DEV 메뉴: 레벨 업/다운/1로 초기화/모든 데이터 초기화.
- **진행/결과**: 구현했다.
- **결정**: 레벨을 내렸다가 다시 올릴 때는 포인트를 또 주지 않는다. 최고 도달 레벨을 기억해서 그 레벨을 넘을 때만 지급한다.

## 18. 맵 개편 + NPC 황금기사
- **사용자 요청**:
  - 시작은 조금 높은 언덕, 왼쪽 끝. 10걸음 뒤 내리막. 이후 점프로 넘는 언덕, 오리가 넘는 완만한 언덕.
  - 오른쪽 끝에 황금기사 레온하르트(황금 갑옷, 깃털 투구) NPC. Space로 대화하고 받기/받지 않기를 고른다.
    - 받기: 거지라고 조롱하며 검만 준다.
    - 받지 않기: 자존심을 칭찬하며 검과 방패를 준다.
    - 마을 방향도 안내한다.
  - 초보자용 검(공격력 5~10), 초보자용 방패(방어력 1, 체력 10), 오른쪽 끝에 빛 기둥(↑을 누르면 "준비 중").
- **진행/결과**: Phaser Arcade는 경사를 지원하지 않아 경사 지형을 직접 구현했다(`src/systems/Terrain.ts`). 나머지도 모두 구현했다.
- **문제와 해결**:
  - 프레임이 떨어질 때 가파른 언덕을 뚫고 지나감 → 구간별 판정과 `prevFrame` 사용.
  - 벽면에 붙어 서는 문제 수정.
  - Phaser가 장면을 역순(UI 먼저)으로 갱신해서, 대화를 닫는 Space가 같은 프레임에 대화를 다시 여는 문제 수정.
  - 대화창 위치를 화면 위쪽으로 옮김.

## 19. 장비창
- **사용자 요청**: 인벤토리 왼쪽에 붙어 같이 열리고 같이 움직이는 13칸 장비창. 더블클릭/우클릭으로 장착·해제. 장비 능력치 반영.
- **진행/결과**: 무기 공격력(범위 내 무작위), 방어력, 최대 HP를 반영했다. 상태창에는 "(+5~10)"처럼 표시한다.
- **문제와 해결**:
  - `bringToTop`이 깊이 정렬을 깨서 툴팁이 창 뒤로 가던 문제 수정.
  - 더블클릭 판정을 `event.detail` 기준으로 변경.

## 20. 장비칸 배치 변경
- **사용자 요청**: 사용자가 직접 그려 준 배치대로 바꾸기.

```
귀걸이  투구    귀걸이
무기    상의    방패
반지    하의    반지
장갑    벨트    장화
        특수장비
```
- **진행/결과**: `src/data/equipment.ts`의 칸 배치를 위와 같이 바꿨다.

## 21. 저장 기능
- **사용자 요청**: 코드를 고쳐도 받은 아이템이 남아 있게.
- **진행/결과**: localStorage 자동 저장을 만들었다. 변경이 있을 때 1초마다, 그리고 페이지를 떠날 때 저장한다. 위치와 몬스터는 저장하지 않는다.

## 22. 손에 든 장비와 검 공격 모션
- **사용자 요청**: 장착한 검·방패를 캐릭터가 들고 있는 모습, 검을 휘두르는 공격 모션.
- **진행/결과**: 캐릭터 위에 겹쳐 그리는 방식으로 구현했다(`src/entities/HeldItems.ts`). 검 휘두르기 모션과 베기 궤적도 추가했다.

- **진행/결과**: `docs/CONVERSATION_LOG.md`, `docs/DEVLOG.md`를 작성하고 git을 초기화해 첫 커밋을 만들었다.
